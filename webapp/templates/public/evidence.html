What this shows

  • Each check fires on the defect it was built for, across scripts and notebooks, scikit-learn, XGBoost and LightGBM.
  • Careful pipelines get no blocking findings, so the checks are not simply noisy.
  • Code that hides its trace, needs the internet or reads files from the author's laptop is caught and reported.

What it does not show

  • Accuracy on real candidates' code. The build team wrote these submissions. Real code is messier; pilot rounds will measure that.
  • Coverage of every library. Tracing supports scikit-learn and the scikit-learn interfaces of XGBoost and LightGBM. Code that converts data to plain arrays can hide row identity; the holdout gap is the backstop.
  • Resistance to AI-written submissions. Whether the task's traps still separate careful work from pipelines generated by AI assistants has not yet been tested.
  • Calibrated weights. The scoring weights are hand-set (rubric v1) and published in every report.

Security and data

Running strangers' code safely, and keeping candidates' data in its place

PipelineProof runs code written by people you have not hired yet. These are the rules it follows, and where your data lives.

Isolation for candidate code

  • Every run gets a fresh sandbox on Modal's gVisor runtime, which intercepts system calls instead of sharing the host kernel.
  • No internet while candidate code runs. Packages are installed beforehand in a separate build step that sees no data.
  • CPU, memory and wall-clock time are capped for each run.
  • Nothing persists between runs: each sandbox is destroyed when its run ends, and only the output folder comes back.
  • No secrets or credentials are ever placed in a sandbox.

Integrity of the result

  • Holdout answers never enter a sandbox. The model's predictions come out and are scored outside it, so code that tampers with its own environment still cannot see the answers.
  • Telemetry from inside the sandbox is treated as untrusted: a run that produces no trace gets a finding of its own.
  • The holdout gap needs no telemetry at all, so it still works if tracing is defeated.

Where data lives

  • The database (accounts, assessments, submissions, reports, audit log) is Postgres hosted by Supabase in London (AWS eu-west-2), encrypted at rest and reached only over TLS.

  • Web requests, including uploads, enter Modal's network through its edge in {{ routing }}, then go to the application.

  • The database tables are not exposed through any public API; only the application's server code can reach them.
  • Pages load nothing from third parties: no analytics, no trackers, fonts served from this site.

Access and accountability

  • Roles inside each organisation: admin (everything, including team and re-runs), reviewer (read reports, decide, release feedback) and recruiter (create assessments, invite candidates, track progress).
  • Passwords are hashed with Argon2id. Sessions are server-side, in secure HTTP-only cookies, with CSRF protection on every form.
  • Every decision, release, export and change is written to an append-only audit log with who did it and when.
  • Candidates reach only their own page, through a private link; they need no account.

Retention

Each organisation sets a retention period (365 days by default). When an assessment has been closed for longer than that, a daily job deletes its candidates, submissions, reports, reviews and feedback. The audit log keeps the record that the deletion happened.

Human decisions

PipelineProof makes recommendations, not decisions. A named reviewer must confirm or override each one with a written reason, candidates are told how their work is assessed, and they can see the evidence about their own submission and contest it. This is designed to support the safeguards UK law sets for significant automated decisions; each employer remains responsible for its own hiring process.
